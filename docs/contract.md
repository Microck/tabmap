# Tabmap contract

Public Chrome/Edge Manifest V3 extension. No dependence on the developer's accounts, machines or private infrastructure.

- Use a locally bundled Geist variable font. Preserve keyboard-accessible form controls, visible focus, dark/light themes and at least 44-pixel action targets. Keep the selected model visible. The expandable privacy explanation must remain available before generation, with a visible summary identifying the shared metadata.
- The Tabset mark is Tabmap's approved identity. Use the same SVG geometry in the theme-aware panel mark and white-on-black 16, 32, 48 and 128-pixel extension icons. Branding changes must preserve the extension key, native host identifier, permissions and grouping behavior.
- Status messages state the current result without repeating visible button instructions. Preserve the pre-apply confirmation that tabs are unchanged, privacy and key-storage warnings, and Undo eligibility information.
- Providers: locally installed Codex with native messaging connector, or a user-chosen OpenAI-compatible Chat Completions endpoint with API key and model. List provider models; allow an explicit API model ID when discovery is unavailable. Never silently switch providers or models.
- Codex owns OAuth login and refresh in a dedicated connector home. Installation requires a separate one-time login; never copy the user's existing Codex credentials or inherit their coding configuration. Reject grouping if Codex reports loaded instruction files. The extension never reads OAuth credentials. Native connector exposes only model discovery and tab grouping, never arbitrary commands or generic RPC. Cancel disconnects the connector and stops only its child Codex process.
- Manual Generate preview checks all current-window ungrouped, unpinned HTTP(S) tabs. Regroup checks only eligible tab IDs not checked successfully in this window during the current browser session. Failed or cancelled generation never advances the checkpoint. Previously checked ungrouped tabs and same-ID navigations are not reclassified by Regroup; Generate preview explicitly rechecks them. Exclude incognito and internal pages. Do not read page contents. Limit 400 submitted tabs and 400 group destinations per check; fail visibly rather than truncating.
- Endpoint URLs must use HTTPS except loopback HTTP. API credentials stay in extension local storage, never browser sync, requests to other origins, logs or distributable files. Request host access only for the configured endpoint. Stored API keys are not encrypted by the extension.
- Every plan partitions the submitted tabs exactly once. Reject missing, duplicate, unknown IDs, unnamed new groups, unknown or repeated destinations, changed existing-group names, and new groups with fewer than two tabs. A named existing group may receive one or more additions. Group names and all tab data render as text, never HTML.
- Both Generate preview and Regroup may extend named groups already in the current window or create new groups. Only submitted tab titles and sanitized URLs, grouping preferences, and destination names/IDs/member counts reach the provider. Existing members' titles and URLs are not sent or reassigned. Each new group needs two distinct supporting tabs; discovery reserves those anchors using bipartite matching, then assignment uses opaque destination IDs and requires every submitted tab. A single submitted tab uses assignment only when destinations exist; without a destination it stays ungrouped without inference. Do not fill omitted assignments, retry automatically, switch models, or force a coverage quota.
- Classification should organize the full window into useful projects or topics, not only near-duplicate pages. Use the selected detail level to decide whether related projects share a broad group or remain separate. Preserve meaningful connections across sites and repositories. Abstain only where metadata does not support a useful connection. Do not enforce a coverage quota or create miscellaneous catch-all groups.
- Grouping preferences are independent of provider settings: Broad, Balanced (default), or Detailed, plus up to 2,000 characters of optional instructions. The same validated preferences reach the selected provider. Full generation saves preferences and clears the old preview. Regroup saves preferences after successfully classifying new tabs and applies them only to those tabs, preserving earlier assignments. A no-new-tabs check leaves preferences and the draft unchanged. Unsaved preferences block Apply while they differ from the saved preferences; reverting restores the existing preview. Group detail never weakens assignment completeness or privacy restrictions.
- Merge and Move edit only the open panel's local preview and require no inference. Both require an explicit destination. Merge retains the destination name and inclusion state. Move can target a new group, any named browser group, or Ungrouped. A new-group source reduced to one tab dissolves into Ungrouped with a visible status; one pending addition to an existing group remains valid. Existing members never appear as movable preview tabs. Names and inclusion choices survive local edits. A replacement preview closes an open edit dialog. Closing or reloading the panel discards unapplied edits and restores the model's preview. Changes reach browser tabs only through Apply.
- Generate preview before apply. Successful generation focuses Preview without changing browser tabs. Regroup incorporates the open preview's renamed/included groups and previous assignments without sending old tab metadata again. It refuses a previous preview changed by anything except added tabs; generate a fresh full preview to recover. No new tabs means no inference or browser mutation and preserves the current draft. Allow local editing, then require a separate Apply action for the same window.
- Apply adds only preview tab IDs to named destinations or new groups. Never rename, recolor, move out, or regroup existing members. Pinned tabs stay intact. Reject stale previews, including changed destination names/member counts. Undo removes only this operation's added tab IDs, then restores their pre-apply order and ungrouped membership without destroying existing groups. Preserve recovery state after every completed mutation and refuse to overwrite intervening changes. Never navigate or close tabs.
- Busy state prevents concurrent operations. Cancel and timeout stop outstanding work. Provider errors are actionable, without secret or raw-response leakage.
- Public distribution requires disclosure of transmitted browsing metadata and host/nativeMessaging permissions. This task does not authorize store submission or publication.

Verification must distinguish a live Codex inference, real browser grouping and undo, API transport verification, and platforms not exercised. Synthetic model success does not prove semantic quality on all real browsing sessions.
